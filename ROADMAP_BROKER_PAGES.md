# Roadmap: страницы брокеров и настройки автоторговли

Все проблемы ниже воспроизведены на локальном сервере (`DB_FILE=…/t.db PORT=8099
ADMIN_PASSWORD=test go run ./cmd/server`) через реальный SPA в браузере. Каждая
задача самодостаточна: файл, строка, что не так, что должно быть, как проверить.

Порядок важен: B-блок (галочки) чинит потерю денег, A-блок — чужие данные.

---

## A. Страница /robinhood показывает данные Webull

### A-1. `state.loaded.broker` — один флаг на две страницы

**Файл:** `go/web/js/app.js:3900` (и `:3935`), `navigate()` на `:1562`.

`/webull` и `/robinhood` — это одна функция `pageBroker()` и один флаг загрузки
`state.loaded.broker`. `navigate()` его не сбрасывает. Поэтому переход
`/webull → /robinhood` **не делает ни одного запроса**: страница Robinhood
рисуется из `state.dashboard`, загруженного для Webull.

Доказано в браузере: после клика по `/webull` уходит
`/api/autotrade/webull/dashboard?refresh=1`, после клика по `/robinhood` —
**ноль запросов**, заголовок при этом «Кабинет Robinhood».

Что показывается чужим: вкладки «Обзор» (баланс, кэш, покупательная
способность, PnL), «Позиции», «Ордера», «Исполненные», все блоки
`Raw … payload`, а также `state.token` и `state.rhStatus`.

**Задача:** сделать флаг загрузки зависимым от брокера. Например
`state.loaded.broker = kind` вместо `true`, а условие перезагрузки —
`if (state.loaded.broker !== kind)`. Сбрасывать на `false`/`null` там, где
сейчас пишется `state.loaded.broker = false` (строки 3941, 3960, 3965, 4069,
4084, 4089, 4093).

**Проверка:** открыть `/webull`, затем `/robinhood` — в Network должен уйти
`/api/autotrade/robinhood/dashboard`. И обратно.

### A-2. `state.brokerTab` тоже общий

**Файл:** `go/web/js/app.js:2503`, обработчик `:3939`.

`const tab = state.brokerTab || (kind === 'robinhood' ? 'connect' : 'overview')`.
Дефолт работает только один раз: если пользователь на `/webull` выбрал «Обзор»,
то `/robinhood` открывается сразу на «Обзоре» (с чужими данными), а вкладку
«Подключение» он не увидит.

**Задача:** хранить вкладку отдельно на брокера — `state.brokerTab[kind]` —
либо сбрасывать `state.brokerTab` при смене `kind`.

**Проверка:** `/webull` → вкладка «Логи» → `/robinhood` должен открыться на
«Подключение».

### A-3. Опасная кнопка: «Закрыть» позицию уходит не тому брокеру

**Файл:** `go/web/js/app.js:4139`.

```js
const r = kind === 'robinhood' ? await API.rhClose(...) : await API.closePosition(...)
```

Брокер берётся из URL, а список позиций (A-1) — из `state.dashboard`, который
может быть от другого брокера. То есть на `/robinhood` можно увидеть позицию
Webull и, нажав «Закрыть», отправить **реальную заявку на продажу в Robinhood**
по бумаге, которой там нет.

Это же касается `data-close-pos` и кнопки тестовой покупки (`:4120`).

**Задача:** после A-1 это уходит само, но нужно добавить страховку: в
`state.dashboard` класть `{ broker: kind, ...dash }` и в `pageBroker()`
отказываться рисовать таблицы, если `state.dashboard.broker !== kind`
(показать «Загрузка…» вместо чужих строк).

**Проверка:** тест на `go/internal/httpapi/api_js_test.go` в стиле уже
существующих — проверить, что в `app.js` есть сравнение брокера дашборда с
`kind`.

### A-4. Журнал сделок не фильтруется по брокеру

**Файл:** `go/internal/httpapi/server.go:1427` (`handleListBroker`),
`go/web/js/app.js:2517`.

`GET /api/broker-trades` отдаёт `ListTrades("broker_trades")` целиком. В таблице
`broker_trades` есть колонка `broker` (`go/internal/store/db.go:144`), но
хендлер её не фильтрует, а UI не фильтрует и даже не показывает: колонка
«Источник» рисует `t.source` (`auto`/`manual`), а не `t.broker`.

Итог: во вкладке «Журнал сделок» на `/webull` видны сделки Robinhood и наоборот.

**Задача:**
1. Добавить в `handleListBroker` необязательный `?broker=webull|robinhood`
   (неизвестное значение — 400, как в остальных хендлерах).
2. `API.brokerTrades(kind)` в `go/web/js/api.js:76`.
3. Добавить колонку «Брокер» (`t.broker`) в таблицу журнала.

**Проверка:** тест в `go/internal/httpapi/handlers_test.go`: две сделки с разными
`broker`, запрос с `?broker=webull` возвращает одну.

### A-5. Tracked orders не фильтруются по брокеру

**Файл:** `go/web/js/app.js:2616-2632`, `go/internal/live/autotrade.go:1023`.

`Logs()` отдаёт `pending`/`recent` из `order_trackers` по всем брокерам.
В таблице есть колонка `broker` (`go/internal/store/db.go:254`), UI её не
использует. На `/robinhood` в «Pending / last tracked orders» висят заявки
Webull, и кнопки «Исполнено у брокера» / «Заявки нет» разрешают чужой трекер.

Та же история с баннером `trackerPersistFail` (`:2634`) — он и так по брокерам,
это правильный образец для подражания.

**Задача:** фильтровать `tracked` по `o.broker === kind` и добавить колонку
«Брокер» в таблицу.

## B. Галочки в настройках выключают то, что включено

### B-0. Корень: у `enabled` нет фолбэка в UI, а в движке он есть

**Файлы:** `go/web/js/app.js:2876-2878` (рендер), `go/internal/live/brokers.go:63`
(`brokerFlags`), `go/web/js/app.js:793` (`brokerAllowFlag`).

В Go для Webull действует легаси-фолбэк: если у вложенного `brokers.webull` нет
ключа, берётся плоский ключ верхнего уровня.

```go
if name == "webull" {
    if !cfgHas(b, "enabled")        { enabled      = asBool(cfg["enabled"]) }
    if !cfgHas(b, "allowNewEntries"){ allowEntries = allowFlag(cfg, "allowNewEntries") }
    if !cfgHas(b, "allowExits")     { allowExits   = allowFlag(cfg, "allowExits") }
}
```

В UI фолбэк реализован **только для двух из трёх** флагов и **не для того
брокера**:

```js
name="${id}Enabled"        ${b.enabled ? 'checked' : ''}                       // фолбэка нет вообще
name="${id}AllowEntries"   ${b.allowNewEntries === true || (b.allowNewEntries == null && ac.allowNewEntries === true) ? …}  // фолбэк есть, но и для robinhood
name="${id}AllowExits"     … то же самое
```

Последствия воспроизведены на конфиге вида
`{enabled:true, allowNewEntries:true, allowExits:true, brokers:{webull:{}, robinhood:{}}}`
(так выглядит конфиг после апгрейда со старой схемы):

| | движок | галочка в UI |
|---|---|---|
| `webull.enabled` | **true** (фолбэк) | **false** |
| `robinhood.allowNewEntries` | **false** | **true** |
| `robinhood.allowExits` | **false** | **true** |

А дальше — то, на что жалуется пользователь. Форма настроек при сохранении
отправляет **все** галочки как есть (`app.js:4218-4220`), поэтому нажатие
«Сохранить» **без единого изменения** записало в конфиг:

```json
"webull":    {"enabled": false, "allowNewEntries": true, "allowExits": true}
"robinhood": {"enabled": false, "allowNewEntries": true, "allowExits": true}
```

То есть Webull, который торговал, **молча выключился**, а Robinhood **молча
получил разрешение на входы и выходы**, которого у него не было. Именно так
выглядит «включаю брокера — они выключаются».

**Задача (одним коммитом, это одна ошибка):**
1. Завести в `app.js` одну функцию `brokerFlag(ac, id, key)`, которая **точно
   повторяет** `live.brokerFlags`: фолбэк на плоский ключ только для `webull`,
   для `robinhood` — `false`. Существующий `brokerAllowFlag` (`:793`) уже почти
   такой — расширить его на `enabled` и использовать в обоих местах.
2. Рендерить все три галочки обоих брокеров через неё (`app.js:2876-2878`).
3. Убрать из рендера фолбэк `ac.allowNewEntries` / `ac.allowExits` для
   `robinhood`.

**Проверка (обязательно воспроизвести до и после):**
```bash
sqlite3 <db> "update settings set data=json_set(data,'$.autoTrading',json('{\"enabled\":true,\"allowNewEntries\":true,\"allowExits\":true,\"brokers\":{\"webull\":{},\"robinhood\":{}}}'))"
```
открыть `/settings` → «Автоторговля», нажать «Сохранить», ничего не меняя.
`GET /api/autotrade/config` до и после должен дать **одинаковые эффективные
флаги**. Сейчас — не даёт.

### B-1. Одноразовая миграция: развернуть плоские ключи в `brokers.webull`

**Файл:** `go/internal/live/config.go:82` (`sanitizeAutoTradingConfig`),
`go/internal/live/brokers.go:27` (`sanitizeBrokers`).

Пока в конфиге живут плоские `enabled`/`allowNewEntries`/`allowExits` вместе с
вложенным `brokers`, любое расхождение фолбэков (B-0) снова разъедется. Надо
избавиться от двух источников правды.

**Задача:** при первом сохранении конфига, если у `brokers.webull` нет ключа
`X`, а плоский `X` есть — записать плоское значение внутрь `brokers.webull.X`.
Плоские ключи после этого можно оставить для обратной совместимости чтения, но
`brokerFlags` должен перестать быть единственным местом, где они видны.

**Проверка:** тест в `go/internal/live/config_test.go`: легаси-конфиг → PATCH с
пустым телом → `brokers.webull.enabled == true`.

### B-2. Форма настроек отправляет флаги, которых пользователь не касался

**Файл:** `go/web/js/app.js:4203-4231`.

Даже после B-0 форма при каждом сохранении переписывает все шесть брокерских
флагов. Это делает её единственным местом, откуда можно случайно всё выключить
(например, сохраняя настройки на вкладке «Общие» — там `form.autoEnabled` нет,
и блок пропускается, а вот на «Автоторговле» — отправляется всё).

**Задача:** сравнивать отправляемые значения с загруженными и слать в `brokers`
только реально изменённые ключи. PATCH-семантика на сервере это уже
поддерживает: `sanitizeBrokers` мержит патч в текущее значение и пропускает
отсутствующие поля.

**Проверка:** тест `charts_map_test.cjs`-стиля или ручная — открыть настройки,
изменить только `lowIBS`, сохранить, убедиться что в запросе нет `brokers`.

### B-3. Кнопка «Включить автоторговлю» и глобальный `enabled` расходятся с брокерами

**Файл:** `go/web/js/app.js:4107` и `internal/live` (`evaluation.live`).

Воспроизведено: после того как оба брокера выключены (`enabled:false` у обоих),
`GET /api/autotrade/status` по-прежнему отдаёт `"live": true`, потому что `live`
считается от глобального `enabled`. UI показывает «Статус: LIVE» и бейдж
`[LIVE]`, хотя торговать не может ни один брокер.

**Задача:** `live` (и бейдж) должны означать «глобально включено **и** есть хотя
бы один брокер с `enabled` и рабочим токеном». Есть готовый помощник
`anyAllow()` (`go/internal/live/brokers.go:92`) — рядом с ним завести
`anyBrokerLive()`.

**Проверка:** тест в `go/internal/live/`: глобально `enabled:true`, оба брокера
`enabled:false` → `live == false`.

## C. Статусы: сейчас непонятно, что означает бейдж

### C-1. Убрать дубль «Токен Webull задан» из подвала

```js
<div id="broker-token" …>${state.token && state.token.present ? 'Токен Webull задан' : ''}</div>
```

есть ожидание этой строки, поправить и их. Информация переезжает в C-2.

### C-2. Три отдельных статуса вместо одного непонятного «OK»

**Файл:** `go/web/js/app.js:2792` (`pageHeader` страницы брокера).

Сейчас в шапке два бейджа:
* `health.status` — сырая константа из Go: `OK`, `EXPIRING_SOON`,
  `NEEDS_REAUTH`, `UNREACHABLE`, `MISSING` (`go/internal/live/health.go:9`).
  Без подписи непонятно, «ОК» — это токен, счёт или торговля.
* `[LIVE]` / `[OFF]` — считается функцией `autotradeLive()` (`:2447`) как
  `cfg.enabled && (tok.hasToken || tok.present)`. Это смешивает **глобальную**
  автоторговлю с наличием **Webull**-токена. На `/robinhood` `state.token` — это
  ответ `/api/autotrade/robinhood/oauth/status`, у которого полей `hasToken` и
  `present` нет вообще (`go/internal/httpapi/robinhood.go:60`), поэтому
  подключённый Robinhood всё равно показывает `[OFF]`.

**Задача:** заменить два бейджа на три подписанных, каждый — про свой вопрос,
и все три — про **того брокера, чья это страница**:

| Плашка | Источник | Значения |
|---|---|---|
| `Автоторговля: включена / выключена` | `ac.enabled` | глобальный тумблер |
| `Торговля через Webull: вкл / выкл` | `brokerFlag(ac, kind, 'enabled')` из B-0, плюс «входы да/нет · выходы да/нет» в подсказке | разрешение конкретному брокеру |
| `Подключение: активно / истекает через N дн. / нужна переавторизация / нет токена / брокер недоступен` | `health.status` + `health.daysLeft` из `/api/brokers/health` | состояние токена |

Русские подписи к константам завести одним словарём рядом с `brokerLabel`
(`app.js:771`), чтобы `NEEDS_REAUTH` больше нигде не вылезал сырым.

`autotradeLive()` после этого используется только для общей плашки — фолбэк на
`state.token` из неё убрать.

**Проверка:** `/robinhood` с подключённым Robinhood и без токена Webull должен
показывать «Подключение: активно», а не `[OFF]`.

### C-3. Тот же сырой статус в настройках

**Файл:** `go/web/js/app.js:2877`.

```js
${esc(h.status || '')}${h.status && h.status !== 'OK' && h.status !== 'EXPIRING_SOON' ? ' — торговля остановлена' : ''}
```

Тот же `NEEDS_REAUTH` без перевода, рядом с галочкой «Включено» — из-за чего

**Задача:** использовать словарь из C-2. Разнести формулировки: галочка — это
«разрешено торговать», статус — «брокер отвечает / не отвечает».

## Порядок работ

1. **B-0** — сначала, это единственный пункт, который прямо сейчас может
   выключить торговлю или включить её не тому брокеру.
2. **A-1**, **A-2**, **A-3** — чужие данные и опасная кнопка.
3. **C-1**, **C-2**, **C-3** — статусы.
4. **B-1**, **B-2**, **B-3** — чистка конфига.
5. **A-4**, **A-5**, **A-6**, **C-4** — фильтры и подписи.

Каждый пункт — отдельный коммит. Перед коммитом:
```bash
cd go && TZ=Pacific/Auckland go test ./... && TZ=America/Los_Angeles go test ./...
```
