## V1 (P1, деньги). Валидация пары порогов при частичном PATCH

**Подтверждено.** `go/internal/live/config.go`, `sanitizeAutoTradingConfig`:

```go
low, lok := finiteNumber(next["lowIBS"])
high, hok := finiteNumber(next["highIBS"])
if hok && high == 0 { ... }
if lok && hok {                      // <-- проверка пары только если оба есть
    ibs.SanitizeThresholds(low, high)
}
```

Сценарий: в сохранённом конфиге нет `highIBS` (свежая установка).
`PATCH {"lowIBS": 0.95}` → `hok == false` → пара не проверяется, значение
ложится. Дальше движок читает `liveHighIBS(cfg)`, который при отсутствии ключа
отдаёт `ibs.DefaultHighIBS = 0.75` (`go/internal/live/config.go:223`).
Эффективная пара `вход ibs<0.95` / `выход ibs>0.75` — интервал (0.75; 0.95)
даёт вход и выход одновременно. Реальные рыночные заявки.

Что сделать:

1. В `sanitizeAutoTradingConfig` после мержа `next` резолвить недостающие
   значения дефолтами: `low` ← `ibs.DefaultLowIBS`, `high` ← `ibs.DefaultHighIBS`,
   если ключа в `next` нет.
2. Гнать **эффективную** пару через `ibs.SanitizeThresholds` всегда, а не под
   условием `lok && hok`.
3. При ошибке — `ErrInvalidAutoConfig` (превращается в 400).

Тесты добавить в `go/internal/live/config_test.go` (или где лежат тесты
sanitize):
* пустой текущий конфиг + `{"lowIBS": 0.95}` → ошибка;
* пустой текущий конфиг + `{"lowIBS": 0.05}` → сохранено, эффективная пара
  `0.05 / 0.75` валидна;
* существующий `{"highIBS": 0.5}` + `{"lowIBS": 0.6}` → ошибка.

Не трогать: проверку `highIBS == 0` — она уже отдельная и корректная.

## V2 (P2). `IsNYSEHoliday` не видит праздники, наблюдаемые в соседнем году

**Подтверждено, но механизм в аудите описан неверно.** Дело не в
префиксном фильтре `NYSEHolidayDates`, а в `go/internal/tradingdate/holidays.go:106`:

```go
y, _, _ := split(date)
for _, h := range nyseHolidays(y) { ... }   // ищем только в списке года самой даты
```

Когда 1 января выпадает на субботу, `ObservedFixed(2022, Jan, 1)` даёт
`2021-12-31`. Но `IsNYSEHoliday("2021-12-31")` смотрит в `nyseHolidays(2021)`,
где этой даты нет. Замерено:

```
IsNYSEHoliday("2021-12-31") -> false      (биржа была закрыта)
NYSEHolidayDates(2021)      -> [... 2021-12-24]        нет 12-31
NYSEHolidayDates(2022)      -> [2022-01-17 ...]        нет 01-01 вообще
```

Влияние реальное: `go/internal/scheduler/scheduler.go:83` и `:97` вызывают
`IsNYSEHoliday`. В такой день планировщик сочтёт сессию торговой и попробует
отправить T-11 / T-1.

Что сделать: в `IsNYSEHoliday` перебирать `nyseHolidays(y)` **и**
`nyseHolidays(y+1)` (наблюдаемая дата может приехать только из следующего
года — сдвиг назад бывает лишь у 1 января). Аналогично добавить эти даты в
`NYSEHolidayDates(year)`: сейчас там префиксный фильтр отбрасывает
`2021-12-31` из списка 2022 года.

Тесты: `IsNYSEHoliday("2021-12-31") == true`;
`NYSEHolidayDates(2021)` содержит `2021-12-31`; существующие тесты по
праздникам остаются зелёными.

## V3 (P2). Даты: `IsValid` пропускает невозможные дни

**Подтверждено, но последствия другие, чем в аудите.** `time.ParseInLocation`
в Go **не** нормализует переполнение — он возвращает ошибку `day out of range`.
Поэтому «сдвига даты» через `utcMidnight` нет. Замерено на `"2024-02-30"`:

| Вызов | Результат | Что это значит |
|---|---|---|
| `IsValid` | `true` | мусор объявлен валидным |
| `DaysBetween("2024-02-28", …)` | `0` | тихо «дат нет разницы» |
| `DayOfWeek` | `-1` | тихо «дня недели нет» |
| `ChartTimestamp` | `1709294400` = **2024-03-01** | вот здесь дата реально уехала |
| `AddDays(…, 1)` | **`"2024-03-02"`** | и здесь тоже |

Сдвиг живёт в `ChartTimestamp` и `AddDays`, потому что они идут не через
`utcMidnight`, а через `split()` + `time.Date`, а `time.Date` нормализует.
Плюс `ChartTimestamp("abc")` даёт `-62169940800` (нулевой год) — `split()`
глотает ошибки `strconv.Atoi`.

Что сделать (три маленькие правки в `go/internal/tradingdate/date.go`):

1. `IsValid` — после regex прогнать через уже существующую `toKey(y, m, d)`
   (она умеет и високосные годы) и вернуть `ok`.
2. `AddDays` уже начинается с `if !IsValid(date)` — после правки (1) он сам
   станет корректным. Ничего дополнительно не делать.
3. `ChartTimestamp` — добавить в начало `if !IsValid(date) { return 0 }`.

Тесты: `IsValid("2024-02-30") == false`, `IsValid("2024-02-29") == true`,
`IsValid("2023-02-29") == false`, `ChartTimestamp("abc") == 0`,
`AddDays("2024-02-30", 1) == ""`.

**Осторожно:** `IsValid` вызывается из `FormatDisplay`, `DayOfWeek`,
`utcMidnight`, `IsNYSEHoliday`, `HolidayName`. После ужесточения прогнать
весь `go test ./...` — если какой-то тест кормит фиктивные даты вроде
`"2024-01-32"`, поправить тест, а не откатывать проверку.
