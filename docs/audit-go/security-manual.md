# Безопасность и устойчивость: ручная часть аудита

Аутентификация, сессии, заголовки, лимиты, инфраструктура. Проверено чтением кода; сравнение с тем, что защищал Node.

---

## S1. [CRITICAL] Пустой `ADMIN_PASSWORD` вне production полностью отключает авторизацию

- **Go:** `httpapi/server.go:193-200`. Если `s.adminPass == ""`, то при `s.prod == true` возвращается 503, а иначе — `next(w, r)` **без какой-либо проверки**. `s.prod` вычисляется в `server.go:48` как `os.Getenv("NODE_ENV") == "production" || os.Getenv("GO_ENV") == "production"`.
- **Проблема:** в `docker-compose.yml:11-21` в блоке `environment:` Go-сервиса **нет ни `NODE_ENV`, ни `GO_ENV`**. Они могут приходить из `env_file: /home/ubuntu/stonks-config/.env`, но это не гарантировано конфигом в репозитории. Если `ADMIN_PASSWORD` окажется пустым (опечатка в имени переменной, потерянный env-файл, ошибка при развёртывании) и при этом не выставлен `NODE_ENV`, весь API открывается анонимно — включая `POST /api/autotrade/execute` и `POST /api/autotrade/webull/test-buy`, то есть отправку реальных ордеров.
- **Дополняет картину:** `docker-compose.yml:26-27` публикует `"3001:3001"` на хост, то есть Go-API доступен в обход Caddy напрямую.
- **Отличие направления отказа:** конфигурация должна падать закрыто. Здесь при отсутствии пароля и отсутствии маркера production система открывается.
- **Фикс:** убрать ветку «нет пароля → пускаем»; при пустом `ADMIN_PASSWORD` всегда отвечать 503 (или не стартовать вовсе). Считать production значением по умолчанию, а режим разработки включать явным флагом. Убрать публикацию порта 3001 наружу либо привязать к `127.0.0.1`.

## S2. [HIGH] Полностью потеряно ограничение частоты запросов

- **Node:** `server/server.js:17` подключает `apiLimiter`/`uploadLimiter` из `middleware/rateLimiter.js`, `server.js:76` вешает `app.use('/api/', apiLimiter)`, `server.js:77` — `uploadLimiter` на загрузку.
- **Go:** ограничителя нет ни в `httpapi/server.go`, ни в `cmd/server/main.go`; в Caddyfile его тоже нет.
- **Последствия:**
  - `POST /api/login` (`server.go:244`) — неограниченный перебор пароля. Единственный тормоз — bcrypt, и то лишь если `ADMIN_PASSWORD` задан хешем; при пароле в открытом виде (`server.go:267` — ветка `body.Password == s.adminPass`) перебор ничем не ограничен и сравнение не constant-time.
  - `POST /api/calc/*` (`httpapi/calc.go:19-28`) — полный бэктест теперь считается **на сервере**, а не в браузере, как было в React. Неограниченный поток таких запросов кладёт торговый процесс, а вместе с ним планировщик T-11/T-1.
  - `POST /api/auth/hash-password` (`server.go:302`) — bcrypt cost 10 на каждый запрос.
- **Фикс:** ограничитель на `/api/`, отдельный жёсткий — на `/api/login`, `/api/calc/*`, `/api/auth/hash-password`.

## S3. [HIGH] Content-Security-Policy утрачен, при том что SPA собирает HTML конкатенацией строк

- **Node:** `server/server.js:39-59` — helmet с полной CSP: `defaultSrc 'self'`, `scriptSrc 'self'`, `objectSrc 'none'`, `frameSrc 'none'`, плюс HSTS, noSniff, referrerPolicy.
- **Сейчас:** `caddy/Caddyfile:14-19` ставит только `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy` и убирает `Server`. **CSP нет.** `X-Frame-Options`/`frame-ancestors` тоже нет.
- **Почему это важно именно здесь:** `go/web/js/app.js` целиком построен на шаблонных литералах и `innerHTML`, экранирование ручное через `esc()` (`app.js:256`). При такой архитектуре CSP — последний рубеж; сейчас его нет. `nginx.conf:6-9` ставит `X-Frame-Options: SAMEORIGIN`, но nginx обслуживает **старый React-фронт**, а Go-SPA идёт через Caddy (`Caddyfile: handle { reverse_proxy server:3001 }`), минуя эти заголовки.
- **Фикс:** вернуть CSP и `frame-ancestors 'none'` в Caddyfile для Go-фронта.

## S4. [HIGH] Сессионная кука без флага `Secure`

- **Go:** `server.go:276` — `http.SetCookie(w, &http.Cookie{Name: "auth_token", Value: tok, Path: "/", HttpOnly: true, SameSite: http.SameSiteLaxMode})`. `Secure` не выставлен.
- **Эффект:** при любом обращении по `http://` (опечатка в адресе, старая закладка, редирект до срабатывания HSTS на первом визите) браузер отправит сессионный токен открытым текстом.
- **Фикс:** `Secure: s.prod` (или всегда true за TLS-прокси).

## S5. [HIGH] Нет ограничения на размер тела запроса

- **Node:** `server/server.js:75` — `express.json({ limit: '5mb' })`.
- **Go:** `server.go:172-175` — `readJSON` делает `json.NewDecoder(r.Body).Decode(dest)` без `http.MaxBytesReader`. Ни один хендлер лимита не ставит (проверено grep'ом: `MaxBytesReader`/`io.LimitReader` в `go/internal` не встречаются ни разу). Единственное исключение — `server.go:395` `ParseMultipartForm(8 << 20)` для загрузки датасета.
- **Эффект:** JSON-тело произвольного размера декодируется в `map[string]any` — исчерпание памяти и падение торгового процесса одним запросом. `nginx.conf:22` ставит `client_max_body_size 50m`, но это относится к старому фронту; в Caddyfile лимита тела нет.
- **Фикс:** `http.MaxBytesReader` в `readJSON` (5 МБ, как было), отдельный лимит для загрузки датасетов.

## S6. [MEDIUM] Неполные таймауты HTTP-сервера

- **Go:** `cmd/server/main.go:38` — задан только `ReadHeaderTimeout: 10 * time.Second`. `ReadTimeout`, `WriteTimeout`, `IdleTimeout` отсутствуют.
- **Эффект:** медленная передача тела запроса удерживает соединение неограниченно; долгий хендлер (бэктест, обращение к провайдеру) не прерывается по таймауту записи. Накопление подвисших соединений исчерпывает дескрипторы.
- **Хорошая новость:** исходящие клиенты таймауты имеют — `webull/client.go:30` и `:65` (15 с), `providers/client.go:42` (30 с), `live/transport.go:39` (15 с). `InsecureSkipVerify` не встречается нигде.
- **Фикс:** выставить `ReadTimeout`, `WriteTimeout`, `IdleTimeout`.

## S7. [MEDIUM] Параметр «запомнить меня» принимается, но игнорируется; срок сессии всегда 30 суток

- **Go:** `server.go:253` объявляет поле `Remember bool`, но `server.go:275` безусловно ставит срок `now + 30*24*60*60*1000`. Значение `Remember` нигде не используется.
- **Эффект:** вход без «запомнить меня» всё равно даёт сессию на 30 дней. Для приложения с доступом к брокерскому счёту срок избыточен.
- **Дополнительно:** кука ставится без `Expires`/`MaxAge`, то есть она сессионная в браузере, а на сервере живёт 30 дней — сама кука пропадёт при закрытии браузера, но токен на сервере останется валидным. Протухшие записи сессий, судя по коду, не вычищаются — таблица растёт неограниченно.
- **Фикс:** короткий срок по умолчанию, длинный только при `Remember`; периодическая очистка протухших сессий.

## S8. [MEDIUM] Сравнение пароля в открытом виде не constant-time

- **Go:** `server.go:264-268` — если `ADMIN_PASSWORD` не начинается с `$2`, выполняется `body.Password == s.adminPass`.
- **Node:** `middleware/auth.js:220-223` — та же логика (`password === ADMIN_PASSWORD`), то есть это не регрессия, а унаследованная проблема.
- **Эффект:** утечка по времени сравнения; в связке с отсутствием ограничения частоты (S2) становится практичнее.
- **Фикс:** `subtle.ConstantTimeCompare`, а лучше — требовать bcrypt-хеш и не поддерживать открытый пароль вовсе.

## S9. [MEDIUM] Ошибка генератора токена сессии игнорируется

- **Go:** `server.go:317-321` — `_, _ = rand.Read(b[:])`. При ошибке `crypto/rand` токеном станет строка из нулей, одинаковая для всех.
- **Эффект:** маловероятно, но это молчаливый отказ в контуре аутентификации.
- **Фикс:** проверять ошибку и отдавать 500.

## S10. [MEDIUM] Нет защиты от CSRF, кроме SameSite=Lax

- **Go:** `server.go:276` — `SameSite: http.SameSiteLaxMode`. CSRF-токена нет, проверки заголовка `Origin`/`Referer` нет.
- **Оценка:** Lax блокирует межсайтовые POST/PATCH/DELETE, поэтому основные состояние-меняющие эндпоинты (включая `/api/autotrade/execute`) на практике защищены. Это не открытая дыра, а отсутствие эшелонирования.
- **Отдельно стоит отметить:** `cookieToken` (`server.go:219-231`) принимает и заголовок `Authorization: Bearer`, что для CSRF безразлично, но расширяет поверхность.
- **Фикс:** проверка `Origin` на состояние-меняющих методах; при желании — `SameSite=Strict`.

## S11. [MEDIUM] `PATCH /api/settings` молча проглатывает некорректный JSON

- **Go:** `server.go:338-347` — `_ = readJSON(r, &body)`. Ошибка разбора игнорируется, дальше выполняется цикл по пустой карте, настройки перезаписываются текущим значением и возвращается 200.
- **Node:** `routes/settings.js:56-79` — валидирует тип тела и отвечает осмысленно.
- **Эффект:** клиент считает, что сохранил настройки, хотя ничего не сохранилось.
- **Фикс:** возвращать 400 при ошибке разбора (как это уже сделано в `handlePutSettings`, `server.go:330`).

## S12. [LOW] Маскированный ключ провайдера больше не отдаётся клиенту

- **Node:** `services/settings.js:63-69` `serializeSettingsForClient` удаляет `polygonApiKey`, но добавляет `polygonApiKeyConfigured` **и** `polygonApiKeyMasked` (первые и последние 4 символа).
- **Go:** `server.go:321-326` удаляет `polygonApiKey` и ставит `polygonApiKeyConfigured`, но `polygonApiKeyMasked` не отдаёт. Кроме того, `Configured` вычисляется по **переменной окружения** `POLYGON_API_KEY`, а удаляется значение из настроек — два разных источника, флаг может не соответствовать действительности.
- **Эффект:** сама утечка ключа закрыта корректно; но UI не может показать, какой ключ настроен, а индикатор «настроен» может врать.

## Сводка регрессий безопасности относительно Node

| Защита | Node | Go |
|---|---|---|
| Ограничение частоты запросов (`/api/`, загрузка) | есть | **нет** |
| Content-Security-Policy | есть (helmet) | **нет** (Caddy не ставит) |
| X-Frame-Options / frame-ancestors | есть | **нет** для Go-SPA |
| Лимит тела запроса (5 МБ) | есть | **нет** |
| CORS с явным origin + credentials | есть | нет (теперь строго same-origin — не хуже) |
| `X-Powered-By` отключён, `trust proxy` | есть | неприменимо |
| HSTS, noSniff, Referrer-Policy | есть | есть (в Caddy) |
| 400 на `autoTrading` в PATCH `/settings` | есть | **нет** (см. A7 в отчёте по автоторговле) |
| Санитизация конфига автоторговли | есть | **нет** (см. A8) |
| Маскирование ключа провайдера в ответе | есть | частично |

## Инфраструктурные замечания

- `docker-compose.yml:14` — `WEBULL_ENABLE_LIVE_TEST_BUY=true` зафиксировано прямо в файле, то есть эндпоинт живой тестовой покупки постоянно включён в развёрнутой системе. Ограничение объёма есть (`live/autotrade.go:526-538`, по умолчанию 1 акция, потолок 100), но сам факт постоянно взведённого «боевого» эндпоинта стоит осознанного решения.
- `docker-compose.yml:26-27` — порт 3001 опубликован на хост в обход Caddy.
- Загрузка датасетов через multipart в Go **поддерживается** (`server.go:395`, `ParseMultipartForm(8 << 20)`) — это не регрессия.
