## Находки

### AUD-016 — P1 — PATCH дня календаря при ошибке чтения затирает календарь

Статус: OPEN (новый)
Файлы: `go/internal/httpapi/server.go:1180-1233`

Корень: `handlePatchCalendarDay` игнорирует ошибку `GetCalendar`, при невалидном JSON начинает с `{}` и вызывает `SaveCalendar`.

Сценарий отказа. БД календаря временно не читается (блокировка, I/O) или в ячейке лежит не-JSON. Оператор в UI отмечает один день как holiday. Хендлер пишет новый документ из пустой карты + этот день. Праздники, короткие дни и `webullCoverageThrough` пропадают. Следующий `RunTick` видит дырявое покрытие или пустые карты.

Почему тесты не ловят: нет теста «GetCalendar вернул ошибку / мусор → PATCH не должен SaveCalendar».

Соседние callers: `handleGetCalendar` (`:1111`) и `handlePrevDay` (`:1125`) тоже глотают ошибку, но не пишут обратно. `RunCalendarExtend` (`scheduler.go:550,566`) — только чтение.

Как доказать: юнит-тест хендлера с `GetCalendar` → error; ожидание 500 и неизменной строки в `calendar`.

### AUD-017 — P1 — T-1 повторный вход смотрит Webull-showcase, не факт исполнения

Статус: OPEN (новый)
Файлы: `go/internal/live/autotrade.go:278`, `execute_all.go:20-107`, `telegram.go:42-56`

Корень: `EvaluateWindow` считает `Decision` по книге `"webull"` + `defaultBroker`. `executeAll` заново решает **по каждому** брокеру и кладёт это в `BrokerDecisions`, но **не подменяет** `ev.Decision`. `runT1Orders` смотрит `exitRes.Decision["action"]`.

Сценарий отказа. У Robinhood открыта позиция с IBS на выход, у Webull книги нет / брокер выключен. `executeAll` отправляет SELL на Robinhood (`Executed=true`). `Decision.action` остаётся `none`. `runT1Orders` не ждёт fill и не делает повторный вход «после полного закрытия» для Robinhood. Симметрично: Webull `exit` в Decision при фактическом skip Webull и входе Robinhood запускает ветку wait-fill не на том брокере.

Почему тесты не ловят: контурные тесты AUD-003 проверяют журнал/имя брокера, не связку Decision ↔ BrokerDecisions в `runT1Orders`.

Как доказать: два брокера, выход только на Robinhood; утверждать, что `runT1Orders` видит `action=exit` или итерирует `BrokerDecisions`.

Связь: AUD-003 (брокер не теряется в executeAll — это так) + этот другой корень в post-exit оркестрации.

### AUD-018 — P1 — сплиты из таблицы не доезжают до прогона Акций/EMA/опционов

Статус: OPEN (новый; родственник AUD-006)
Файлы: `go/web/js/app.js:4530-4531,4611-4616,4584,4646`; `go/internal/httpapi/calc.go:71-89,113-142`; `go/internal/backtest/ema.go` (нет import `splits`); `go/internal/backtest/options.go` (нет import `splits`)

Корень: `calcTickerRefs` шлёт только `{ticker}`. `runStocks` / `runEma` / `runOptionsMulti` не кладут `splits` в payload. `RunEmaZone` и `RunMultiOptions` всё равно не вызывают `splits.AdjustOHLC`. `calcClean` берёт `barsOrDataset` и `req.Options.Splits`, не top-level `req.Splits`.

Сценарий отказа. Оператор завёл сплиты на `/split`, OHLC в датасете сырой (apply-splits не нажимали). Прогон Акций считает входы по нескорректированным ценам; вкладка «Сплиты» при этом показывает события. EMA/опционы — то же.

Почему тесты не ловят: golden'ы либо без сплитов, либо с уже скорректированными барами.

Как доказать: датасет с raw OHLC + строка в `splits`; `POST /api/calc/single-position` без поля `splits` vs с ним — разные сделки.

### AUD-019 — P1 — битый JSON настроек маскируется под дефолты и может быть затёрт

Статус: OPEN (новый; родственник AUD-002)
Файлы: `go/internal/store/db.go:906-908,985-992`; `go/internal/live/autotrade.go:26-32,40-51`

Корень: `SettingsErr` при `json.Unmarshal` ошибке возвращает `defaultSettings()` и **`nil` error**. `SetSettingsKeys` при том же мусоре начинает с `stored={}` и пишет overlay.

Сценарий отказа. Строка `settings.data` портится. `AutoConfig()` видит `enabled: false` — торговля останавливается (это fail-closed, хорошо). Оператор меняет один ключ в настройках. `SetSettingsKeys` сохраняет почти пустой объект + этот ключ. Восстановить прежний autoTrading из БД уже нельзя.

Почему тесты не ловят: нет теста «corrupt settings JSON → SettingsErr error, SetSettingsKeys не COMMIT пустышки».

Как доказать: записать `settings.data='not-json'`; `SettingsErr` должен вернуть error; PATCH одного ключа не должен давать валидный JSON без старых ключей.

### AUD-002 — P1 — ошибка чтения журнала выглядит как «позиции нет»

Статус: OPEN (денежный путь подтверждён, не только fill)
Файлы: `go/internal/live/track.go:707-725`; `go/internal/live/trade_record.go:12-14,44`; `store/db.go:1415-1426`; `store/live_persist.go:549-573`

Корень: `ListTrades` при ошибке возвращает `nil, err`. `OpenBrokerTrade(nil)` — nil. `awaitFlatAfterExit` делает `rows, _ := ListTrades(...)` и если open нет — `return true` («плоско, можно входить»). Комментарий рядом про DB error относится только к `FindPendingTracker`, не к журналу. `getTrade` по-прежнему `row, _ := GetTrade`.

Сценарий отказа. T-1 выход отправлен. SQLite busy (`MaxOpenConns=1`). `awaitFlatAfterExit` видит ошибку журнала как пустую книгу и сразу зовёт `executeWindow` на вход. Если следующий `ListTrades` уже проходит, а позиция ещё open — второй SELL; если `heldSymbolsOn` тоже пуст — второй BUY в открытую ногу. `EvaluateWindow` на устойчивой ошибке журнала fail-closed (`journal_unavailable`); дыра — переходный отказ внутри ожидания fill.

Почему тесты не ловят: нет теста «ListTrades error during awaitFlatAfterExit after submitted exit». Реестр помечал `track.go:709,724` как NEEDS_RECHECK — теперь это подтверждённый fail-open.

Как доказать: после submitted exit заставить `ListTrades("broker_trades")` вернуть error; `awaitFlatAfterExit` не должен быть true.

## Подсистемы — вердикт каждой

### 1. Пороги IBS и паритет live ↔ бэктест ↔ SPA

**Проверено.** Исторический A1/A2 (подмена нуля) на HEAD закрыт в `liveLowIBS`. Live/clean/single/calc IBS API ходят через `ibs.Is*Signal`. SPA клампит IBS. Новых P0 нет.

### 2. Live-движок: monitor, autotrade, sizing, safety

**Находки: AUD-017, AUD-021, AUD-002 (awaitFlat), AUD-024, AUD-025, AUD-026.** EvaluateWindow fail-closed на watchlist/journal. `placeMarket` abort на отменённом ctx. Ручной путь и retry id — нет.

### 3. Трекеры, журнал, идемпотентность

**Находки: AUD-002, AUD-024, AUD-026.** Условный UPDATE статуса трекера на месте. `brokerForTracker` без подмены имени. Авто-Ambiguous трекается, ручной — нет. Гонка ResolveTracker vs poll — FIXED_UNVERIFIED в реестре, не переигрывал `-race`.

### 4. Брокеры: Webull и Robinhood

**Находки: AUD-021; пробел: живой API.** `GetRobinhoodOAuth()` глотает scan error (`store/robinhood.go:16`). Disconnect: `Revoke()` error игнорируется, ответ `ok: true` (`httpapi/robinhood.go:47-51`) — подозрение P2, не разворачивал как отдельный AUD. Dashboard при отсутствии брокера — 200 и пустые positions плюс `error: not connected`. Живые credentials не использовались.

### 5. Планировщик T-11 / T-1 / after-close

**Проверено + AUD-016 косвенно.** `RunTick` fail-closed на чтении календаря. `RunCalendarExtend` по-прежнему `raw, _ := db.GetCalendar()` — при ошибке coverage пустой, может лишний раз дергать импорт (P3, не отдельный ID). Lease T-1 по реестру VERIFIED; не переигрывал.

### 6. Telegram-транспорт мониторинга

**Проверено.** `finishSend` возвращает ошибку, не успех (`telegram.go:345-358`). T-1: `MarkT1ExecutionFinished` до отправки отчёта — намеренно (ордера уже вышли). T-11 ордеров не ставит. День без сделки: не доказывал отсутствие «тихого дня» отдельным сценарием → **пробел**.

### 7. HTTP API, auth, calc

**Находки: AUD-016, AUD-018, AUD-020.** Пустой пароль — 503. PUT/PATCH settings проверяют `SetSettingsKeys` error. PATCH watchlist ошибки чтения отдаёт 500 (`server.go:1245-1247`). calcClean не прогоняет top-level `splits`.

### 8. Vanilla SPA

**Проверено с оговоркой.** Торговая дата в `fmtTradingDate` — строки. `new Date(raw)` в `formatDateTimeET` только после отсечения `YYYY-MM-DD`. `isMarketOpen` — wall-clock NY. ## Псевдокод и проверка логики

Разбор на HEAD `0f4f6b9`. «Логика сходится» = соответствует инвариантам CLAUDE.md на прочитанных ветках. Находки — ссылки на AUD-*.

### 1. IBS

```
SanitizeThresholds(low, high):
  reject unless both in [0,1] and low < high     # 0 валиден

IsEntrySignal(ibs, low):
  if ibs not finite → false
  return ibs < resolve(low, 0.10)                 # строго, 0.10 не вход

IsExitSignal(ibs, high):
  if ibs not finite → false
  return ibs > resolve(high, 0.75)
```

Логика сходится с инвариантом. Live/SPA не должны подменять порог до этих предикатов — на HEAD `liveLowIBS` не подменяет 0.

### 2. Планировщик

```
loop every tick:
  today, clock = NYSE(now)
  raw, calErr = GetCalendar()
  trading = IsTradingDay(clock, cal)              # weekend / holiday map / computed NYSE holiday
  if trading and (calErr or coverage < today):
      alert; trading = false                      # fail-closed
  if trading:
      until = closeMin - nowMin
      if until in [10,12] or [0,2]:
          Aggregate(until)                        # T-11 text only; T-1 orders
      if until just missed: reportMissed
  PollTrackers()
  TokenHealth()
  if after close 15..31 min: actualize async
```

Логика T-11/T-1 окон сходится. Дыра не в тике, а в PATCH календаря (AUD-016) и в том, что SPA/GET скрывают тот же отказ (AUD-020).
