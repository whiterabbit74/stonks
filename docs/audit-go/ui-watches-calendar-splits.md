### [CRITICAL] "Пересчитать датасет" (apply-splits) полностью отсутствует в Go UI
- **React:** src/components/SplitsTab.tsx — нет прямой кнопки в SplitsTab, но SplitPage.tsx:278 `applySplits()` → `DatasetAPI.applySplitsToDataset(selected)` кнопка "Пересчитать датасет". Сама фича — центральная: пересчитать OHLC датасета с учётом сплитов.

Кнопки нет ни на /split, ни на /data.

- **Фикс:** добавить `applyDatasetSplits: (id) => API.post('/api/datasets/' + encodeURIComponent(id) + '/apply-splits')` в api.js и кнопку "Пересчитать датасет" в pageSplits() (или на карточке датасета на /data), с обновлением списка датасетов после применения.

### [MEDIUM] `monitorStats` (Go) и `calculateMonitorTradeMetrics` (React) считают "netProfit" и "profitFactor" на разной основе
- **React:** src/lib/monitor-trade-metrics.ts:80-141 — `netProfit = finalBalance - initialCapital` (компаундинг через `pnlPercent`, баланс от `initialCapital`), `profitFactor = grossProfitPct / grossLossPct` (в **процентных пунктах**, не в долларах). `avgHoldingDays = totalHoldingDays / holdingDaysCount` — делит только на сделки, где известна длительность (не на все закрытые).
- **Go:** go/web/js/app.js:810-828 `monitorStats` — `net` считается как **арифметическая сумма** `t.pnlAbsolute` по всем закрытым сделкам (не через компаундинг от initialCapital); `pf = grossWin / Math.abs(grossLoss)` — в **долларах** (`pnlAbsolute`), а не в процентах; `hold` делится на `closed.length` (все закрытые сделки), а не на число сделок с известной длительностью (в шаблоне отрисовки: `stats.hold / stats.closed.length` — app.js:1624).
- **Эффект:** цифры "Чистая прибыль" и "Профит-фактор" на /watches в Go-версии математически не совпадают с тем, что показывала бы идентичная логика в React (особенно при применении маржинальной симуляции — `applyMonitorMarginSimulation` домножает `pnlPercent`, но `pnlAbsolute` для не-`Number.isFinite` случаев остаётся нетронутым, поэтому сумма pnlAbsolute может быть внутренне неконсистентна с pnlPercent-компаундингом).
