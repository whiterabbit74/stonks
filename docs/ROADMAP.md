# Единый roadmap проекта

Актуальная очередь работ для `mktorder_com`. Этот файл заменяет разрозненные
roadmap-документы в корне и `docs/audits/`. Аудиты остаются источниками
доказательств; их выводы не считаются автоматически закрытыми или текущими
без проверки на ревизии, указанной в реестре.

Дата сведения: 2026-09-05. Checkout: `main`, HEAD `368a00b`.

## Правила состояния

- **OPEN** — источник содержит подтверждённую нерешённую проблему.
- **NEEDS_RECHECK** — источники конфликтуют или проверены на другой ревизии.
- **VERIFIED** — исходный сценарий и затронутые пути повторно проходят на одной
  зафиксированной ревизии; одних зелёных общих тестов недостаточно.
- Исправления делать отдельными логическими коммитами. Пуш и деплой — только
  по отдельной прямой просьбе.
- Для денежного контура сначала тест на отказ/гонку, затем обычные тесты,
  затем ручной сценарий с тестовыми брокерами.

## Очередь

### 0. P0 — деньги, состояние и безопасность торговли

**Статус: OPEN / NEEDS_RECHECK по отдельным пунктам.**

1. Сделать атомарными закрытие сделки и изменение открытой позиции: условный
   `UPDATE`, проверка `RowsAffected`, транзакция там, где меняются связанные
   строки.
2. Запретить fail-open: ошибка чтения pending-трекера, позиции, настроек или
   журнала должна останавливать новую заявку и возвращаться оператору как
   ошибка, а не как «ничего нет».
3. Разделить брокера во всех путях исполнения, трекера, ручного закрытия,
   журнала и сверки; исключить fallback на default-брокера.
4. Сохранять идентификатор заявки до отправки или иметь устойчивый журнал
   намерения; частичное исполнение и повторный запуск не должны создавать
   дубликаты.
5. Исправить опасные операционные скрипты и ограничения контейнера после
   отдельной проверки целевого окружения; production-базу не удалять без
   явного режима подтверждения.

Источники: `AUDIT_FULL_2026-09-05.md`,
`AUTOTRADE_READONLY_AUDIT_2026-09-04.md`,
`docs/audits/AUDIT_2026-09-05.md`, `docs/audits/REGISTRY.md`.

### 1. P1 — ложное состояние, планировщик и данные

**Статус: OPEN / NEEDS_RECHECK.**

1. Проверять ошибки записи во всех mutation-хендлерах, сохранении настроек,
   трекеров, календаря, сессий и уведомлений; не отвечать `ok: true` после
   сбоя.
2. Передавать единый снимок времени через планировщик и гарантировать T-11/T-1
   даже при задержке тика; не считать задачу выполненной до успешной отправки.
3. Свести IBS-пороги, комиссии, резерв капитала, CAGR (среднегодовая доходность)
   и обработку сплитов к одному источнику истины между Go и SPA.
4. Сделать PATCH частичным по смыслу: не затирать открытые позиции, пороги и
   чужие ключи настроек отсутствующими полями.
5. Проверить календарь NYSE (Нью-Йоркская фондовая биржа), невозможные даты,
   сокращённые дни и импорт с неполным ответом провайдера.

Источники: `ROADMAP_VERIFIED_2026-09-05.md`,
`docs/audits/PROJECT_AUDIT_ROADMAP.md`,
`docs/audits/SYSTEMIC_DEFECTS_ROADMAP_2026-09-04.md`.

### 2. P1–P2 — страницы брокеров и API

**Статус: NEEDS_RECHECK.**

Проверить изолированное состояние Webull и Robinhood: баланс, заявки,
историю, логи, вкладки, бейджи `[LIVE]/[OFF]`, флаги entries/exits и ручное
закрытие. Исправлять общий источник состояния, а не добавлять условие в каждый
рендер. Ошибку авторизации брокера не выдавать за истёкшую сессию сайта.

Источник: бывший `docs/audits/BROKER_PAGES_ROADMAP.md` и его реестр.

### 3. P1–P2 — UI и адаптивность

**Статус: FIXED_UNVERIFIED по части пунктов; остальное NEEDS_RECHECK.**

Повторно пройти реальные маршруты на 360, 768, 1024 и 1440 px: нижняя
навигация не перекрывает контент, табы показывают возможность прокрутки,
таблицы имеют безопасный mobile-вид, действия используют доступные иконки,
пустое состояние брокера не похоже на данные. Для каждого исправления сохранить
скриншот и ссылку на коммит.

Источники: `docs/audits/UI_VISUAL_AUDIT_2026-09-05.md`,
`docs/audits/visual-audit-2026-09-05.md`,
`docs/audits/visual-audit-codex-2026-09-05.md`.

### 4. P2 — безопасность и эксплуатация

**Статус: OPEN / NEEDS_RECHECK.**

Ограничить HTTP-журнал до рейт-лимита (ограничителя частоты), закрыть права
резервных архивов с токенами, зафиксировать безопасную версию Go и образа,
добавить лимиты контейнеру `server`, а затем повторить сканирование и проверку
деплой-скриптов. Не менять production и не публиковать секреты в артефактах.

Источник: `SECURITY_AUDIT.md` и бывший
`docs/audits/SECURITY_ROADMAP.md`.

### 5. P2–P3 — качество и упрощение

После P0/P1: убрать мёртвые ручки и поля, дубли списков/порогов и мёртвый код;
сократить четыре дневных движка только после отдельного parity (сверки
поведения) теста. Обновить документацию и ссылки на этот файл.

Источники: `docs/audits/FULL_AUDIT_ROADMAP_2026-09-04.md`,
`docs/audits/PROJECT_AUDIT_ROADMAP.md`.

## Минимальная проверка каждого фикса

```text
go test ./...
go test -race ./...
go vet ./...
```

Для изменений SPA — соответствующий тест JavaScript и ручной маршрут в
указанных viewport. Для торговли — отдельный отказ брокера/БД и проверка
журнала, позиции, трекера и повторного запуска. Результат заносится в
`docs/audits/REGISTRY.md` вместе с ревизией и коммитом.
