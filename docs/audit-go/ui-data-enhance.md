Сравнение:
- React: `src/components/DataUpload.tsx`, `src/components/DatasetLibrary.tsx`, `src/components/DataEnhancer.tsx`, `src/components/ConfirmModal.tsx`, `src/components/ui/Modal.tsx`, `src/components/ui/ProviderBadge.tsx`, `src/lib/formatters.ts`, `src/lib/ticker-data.ts`, `src/lib/api.ts`

### [CRITICAL] Сплиты теряются при загрузке нового тикера через /enhance
- **React:** `src/components/DataEnhancer.tsx:163,191` — сплиты, вернувшиеся от провайдера (`payload.splits`), передаются в `saveDatasetToServer(targetTicker, undefined, metadata, splits)`; стор (`src/stores/index.ts:362-389`, поле `...(Array.isArray(splits) && splits.length > 0 && { splits })`) кладёт их в тело `POST /api/datasets`, откуда сервер сохраняет их в `splits.json` (`server/src/routes/datasets.js:113-119`).
- **Go:** `go/web/js/app.js:2299-2302` — `enhanceFetch()` получает `r.data`/`r.splits` от `/api/fetch/{provider}/{symbol}` (сплиты реально приходят, см. `handleFetchProvider`, который вызывает тот же `Providers.Historical`), но при сохранении вызывает `API.saveDataset({ ticker, name: ticker, data: bars })` — поле `splits` не передаётся вообще.
- **Эффект:** при первой загрузке тикера через Go-версию сплиты, обнаруженные провайдером, безвозвратно теряются (не попадают ни в датасет, ни в `splits`-хранилище). Это ломает корректировку цен и бэктест для любого тикера, у которого был сплит, — тихая порча данных без предупреждения пользователю.
- **Фикс:** в `enhanceFetch` передавать `splits: r.splits || []` в `API.saveDataset(...)`, на бэкенде `savePayload` (`go/internal/httpapi/server.go:427-440`) — сохранять `payload["splits"]` в splits-хранилище аналогично Node.

### [HIGH] У сохранённого через /enhance датасета не сохраняется название компании
- **React:** `src/components/DataEnhancer.tsx:189-191` — `getTickerInfo(targetTicker)` подтягивает `companyName` из локального каталога и кладёт в `metadata`, которое стор пишет в `dataset.companyName` (`src/stores/index.ts:388`).
- **Go:** `go/web/js/app.js:2302` — `API.saveDataset({ ticker, name: ticker, data: bars })` не содержит `companyName`, хотя `state.tickerCatalog`/`POPULAR` содержит `t.name` для того же тикера (используется только для рендера карточки каталога, `go/web/js/app.js:785`).
- **Эффект:** после загрузки тикера на `/data` карточка показывает только тикер без названия компании (см. следующую находку) — постоянная деградация отображения, не лечится обновлением датасета вручную (нет UI для этого, кроме модалки редактирования, которую нужно открывать вручную для каждого тикера).
- **Фикс:** при сохранении передавать `companyName` из найденной записи каталога (`list.find(t => t.symbol === ticker)?.name`).

### [MEDIUM] Карточки датасетов не подставляют название компании по каталогу как fallback
- **React:** `src/components/DatasetLibrary.tsx:525-526,642-643` — `const companyName = dataset.companyName || tickerInfo?.name` (и в `DatasetCard`, и в `CompactDatasetCard`), где `tickerInfo = getTickerInfo(dataset.ticker)`.

- **Эффект:** даже если у датасета нет `companyName` (см. предыдущую находку), React всё равно покажет имя компании по справочнику тикеров, а Go — нет. Усугубляет CRITICAL/HIGH выше.
- **Фикс:** в `pageData()` при рендере карточки делать `d.companyName || (state.tickerCatalog.find(t => t.symbol === d.ticker) || {}).name`.

### [HIGH] На /enhance отсутствует live-автокомплит с клавиатурной навигацией
- **React:** `src/components/DataEnhancer.tsx:261-295` — при вводе текста в поле поиска показывается выпадающий список (`role="listbox"`, до 8 подсказок), с подсветкой активного пункта, поддержкой `ArrowUp`/`ArrowDown`/`Enter`/`Escape` (`handleSearchKeyDown`, строки 88-118), индикатором «уже загружен» (зелёная галочка) и иконкой скачивания при наведении.
- **Go:** `go/web/js/app.js:1205-1224` (разметка) и `2271-2316` (обработчики) — есть только текстовое поле + кнопка «Загрузить» и полная сетка каталога ниже; никакого выпадающего списка подсказок, никакой клавиатурной навигации по нему нет.
- **Эффект:** пользователь, ожидающий быстрый автокомплит (как в React), должен листать всю сетку каталога вручную; UX поиска тикера значительно беднее.
- **Фикс:** добавить дропдаун с топ-N совпадений по `catalogFiltered()`/`state.enhanceQuery` под полем ввода с обработкой стрелок/Enter/Escape.

### [MEDIUM] На /enhance нет защиты от повторного/параллельного клика и нет per-card индикатора загрузки
- **React:** `src/components/DataEnhancer.tsx:129-141,137,151` — есть `isLoading` (блокирует кнопку и клики по карточкам через `disabled={isLoading}`), `latestDownloadRequestIdRef` защищает от гонки устаревших ответов, `loadingTicker`/`loadingStage` показывают спиннер на конкретной карточке (`isCurrentlyLoading`, строки 395-398).
- **Go:** `go/web/js/app.js:2283,2311` — `data-esym` кнопки просто вызывают `enhanceFetch(...)` без каких-либо проверок состояния; нет `disabled`, нет спиннера на карточке, нет защиты от гонки при быстром повторном клике или клике по нескольким тикерам подряд.
- **Эффект:** быстрый двойной клик по одной карточке или клик по нескольким тикерам подряд может привести к параллельным сохранением и непредсказуемому порядку записи; пользователь не видит, что уже идёт загрузка именно этого тикера.
- **Фикс:** ввести `state.enhanceLoadingSymbol`, блокировать повторный вызов `enhanceFetch` для того же/любого символа, пока не завершится текущий, и подсвечивать карточку спиннером.

### [HIGH] Ошибка первоначальной загрузки списка датасетов проглатывается молча

- **Фикс:** передавать `?provider=` из `resultsRefreshProvider` в запросе, на бэкенде читать `st["resultsRefreshProvider"]` вместо `enhancerProvider`, с фоллбеком на `finnhub`.

## Проверено и подтверждено НЕ регрессией (для полноты)

- **Multipart upload:** реальный React-фронтенд НЕ использует multipart для `/data`/`/enhance` — `DataUpload.tsx` вообще не содержит формы загрузки файла (`parseCSV` в `src/lib/validation.ts:230` существует, но нигде не вызывается из UI, кроме тестов), а `DataEnhancer.tsx` сохраняет датасет через `DatasetAPI.saveDataset()` (`src/lib/api.ts:549-579`), которая шлёт `Content-Type: application/json`, не `multipart/form-data`. И Node (`server/src/routes/datasets.js:87-96`), и Go (`go/internal/httpapi/server.go:391-415`, `394` — ветка `multipart`, иначе `readJSON`) поддерживают оба варианта тела запроса. Реальный фронтенд-код на обеих платформах использует JSON-тело, так что несоответствие форматов здесь не является пользовательской регрессией — но стоит иметь в виду при появлении новых мест, где нужна загрузка CSV-файла (эта функциональность нигде не подключена к UI ни в React, ни в Go).
- **Формат дат в /enhance-запросах:** оба бэкенда используют `unix timestamp` для диапазона (40 лет назад — сейчас) и `adjustment=none`, никакого `new Date()`/локальных смещений на этих путях не найдено.
- **`dateRange`/`dataPoints` при POST /api/datasets:** Go вычисляет их на сервере (`go/internal/store/db.go:335+`), так что путь через JSON-тело не теряет эти поля (в отличие от опасения из ТЗ).
- **Кнопки "Дальше"/"Перейти к результатам"** (`DataUpload.tsx:49-57`, `DataEnhancer.tsx:451-459`) в реальности не рендерятся ни на одном роуте — `<DataUpload />`/`<DataEnhancer />` монтируются без `onNext` (`AppRouter.tsx:433-434`), это мёртвый код в самом React, поэтому отсутствие аналога в Go не является регрессией.
