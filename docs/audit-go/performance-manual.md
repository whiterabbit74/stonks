## P1. [HIGH] Каждая оценка сигнала перечитывает весь датасет тикера с диска

- **Go:** `live/telegram.go:376` — `bars, adj, _ := e.DB.GetOHLC(sym)` вызывается в `evalWatch` для **каждого** тикера при **каждой** оценке. `store/db.go:1005 GetOHLC` → `db.go:291 GetDataset` → `SELECT date, open, high, low, close, adj_close, volume FROM ohlc WHERE ticker = ? ORDER BY date` без ограничения — то есть выгружаются и материализуются **все** бары (за 10 лет это ~2500 строк на тикер). Кэша нет.
- **Умножается на:** `live/telegram.go:111` (агрегация T-11/T-1, каждые 20 с в окне), `live/autotrade.go:216` (`Evaluate`, вызывается из `Execute`, `Status` и хендлера `GET /api/autotrade/status`).
- **Дополнительно:** `telegram.go:383-384` считает IBS по **всему** массиву (`indicators.IBS(bars)`), чтобы взять единственное последнее значение. Плюс `telegram.go:392` `EvaluatePriceIntegrity(sym, bars, ...)` снова обходит все бары.
- **Как было в React:** бэктест и индикаторы считались в браузере по уже загруженным в стор данным; сервер отдавал датасет один раз.
- **Фикс:** кэш последних N баров на тикер с инвалидацией по обновлению датасета; либо запрос вида `ORDER BY date DESC LIMIT N` там, где нужен только хвост; IBS считать по последнему бару, а не по всему ряду.

## P2. [MEDIUM] Единственное соединение с БД сериализует всё приложение

- **Go:** `store/db.go:34` — `sqlDB.SetMaxOpenConns(1)`.
- **Оценка:** для SQLite это разумная защита от блокировок (WAL включён в `db.go:30`), но следствие в том, что **любой** долгий запрос блокирует все остальные. Полная выгрузка датасета (P1) внутри горутины планировщика останавливает обработку HTTP-запросов; серия бэктестов через `POST /api/calc/*` — тем более.
- **Фикс:** вынести тяжёлое чтение из-под общего соединения (отдельный read-only пул на WAL это позволяет) либо кэшировать горячие данные в памяти.

## P3. [MEDIUM] SPA перерисовывает страницу целиком и пересоздаёт все графики на каждое изменение состояния

- **Go:** `web/js/app.js:2133 renderPage()` — `Charts.destroy()` (строка 2145), затем `document.getElementById('page-root').innerHTML = pageHTML()` (2147). Вызывается 80 раз по файлу — на каждое действие пользователя, а не только на смену страницы.
- **Эффект:** при каждом рендере уничтожаются и заново создаются все экземпляры lightweight-charts (выделение canvas, повторная подача рядов данных), пересобирается вся разметка страницы, включая таблицу сделок. Побочно теряются позиция прокрутки, фокус ввода и масштаб/зум графиков.
- **Как было в React:** согласование виртуального DOM + мемоизация; графики жили между рендерами, менялись только данные рядов.
- **Фикс:** переиспользовать экземпляры графиков (`setData` вместо пересоздания); точечно обновлять узлы там, где меняется одно значение.

## P4. [MEDIUM] Расчёт бэктеста переехал с клиента на сервер без ограничения нагрузки

- Раньше: React считал в браузере пользователя (`src/lib/backtest.ts`).
- Сейчас: `httpapi/calc.go:19-28` — восемь эндпоинтов `POST /api/calc/*` считают на сервере, в том же процессе, что и планировщик торговли.
- **Эффект:** тяжёлый расчёт конкурирует за CPU и за единственное соединение с БД (P2) с контуром T-11/T-1. Ограничения частоты нет (см. S2), лимита тела запроса нет (см. S5).
- **Фикс:** как минимум ограничение частоты и лимит объёма входных данных на этих эндпоинтах; при возможности — вынести расчёт из процесса, обслуживающего торговлю.

## P5. [LOW] Открытие страницы брокера делает восемь параллельных запросов, часть из них тяжёлые

- **Go:** `web/js/app.js:2664-2673` — `Promise.all` из восьми вызовов. Среди них `API.autoStatus()`, который на сервере разворачивается в `Evaluate()`: живой запрос котировки к провайдеру **на каждый** отслеживаемый тикер плюс полная выгрузка датасета на каждый тикер (P1). Следом ещё `API.webullBatch(symbols)`.
- **Эффект:** заметная задержка открытия страницы и всплеск обращений к внешнему провайдеру. При провайдере с жёстким лимитом (AlphaVantage — порядка 5 запросов в минуту) открытие страницы способно исчерпать квоту.
- **Фикс:** отдавать на статус закэшированный снимок последней оценки вместо принудительного пересчёта, либо ввести параметр «пересчитать» и по умолчанию не пересчитывать.
