## Находки

### AUD-039 — вход возможен по тикеру вне списка наблюдения

`decideLiveAction` ([`autotrade.go`](../../go/internal/live/autotrade.go))
получает `symbols` (вселенная из `ListWatches`), но использует его **только**
для проверки `len(symbols) == 0`. Перебор кандидатов на вход идёт по `quotes`:

```go
for _, q := range quotes {
    ...
    if ibs.IsEntrySignal(v, low) && v < bestIBS { best = q }
}
```

А `EvaluateWindow` расширяет `quoteSymbols` за пределы вселенной: туда
добавляется символ `open`-сделки и символы **всех** открытых строк
`broker_trades`, включая чужого брокера. Для символа без строки watch пороги
берутся из глобального конфига (или дефолтные), `evalWatch` отдаёт `ok=true`
по живой котировке — и он становится полноправным кандидатом.

Сценарий: список наблюдения `QQQ, SPY`; Robinhood держит открытую сделку по
`XYZ` (в журнале), Webull плоский и включён. `XYZ` попадает в `quotes`, его IBS
ниже порога и ниже, чем у QQQ/SPY → Webull покупает `XYZ`. Это нарушает
правило из CLAUDE.md: инструмент выбирается «из списка наблюдения».

Доказательство (временный тест, в дерево не коммитился):

```go
quotes := []map[string]any{
  {"symbol":"QQQ","ok":true,"ibs":0.5,"thresholds":map[string]any{"lowIBS":0.1,"highIBS":0.75}},
  {"symbol":"XYZ","ok":true,"ibs":0.02,"thresholds":map[string]any{"lowIBS":0.1,"highIBS":0.75}},
}
decideLiveAction(quotes, []string{"QQQ"}, map[string]float64{}, nil, nil, true, true)
// action:entry symbol:XYZ reason:lowest_ibs_signal
```

Выход по такому символу — поведение верное (позицию надо закрывать), так что
фильтровать нужно только ветку входа.

### AUD-040 — `CloseTradePair` закрывает сделку по цене 0 и пишет −100% PnL

`CloseTradeByID` отвергает неположительную цену выхода
([`db.go:1426`](../../go/internal/store/db.go)), а `CloseTradePair`
([`db.go:1448`](../../go/internal/store/db.go)) такой проверки не имеет.
`TradeCloseFields` считает `pnlPercent = (0 - entryPrice)/entryPrice*100`.

Путь: `recordFill` (`action == "exit"`) вызывает `CloseTradePair(..., fillPrice, ...)`
без проверки `fillPrice > 0`. Для входа тот же файл цену 0 намеренно не пишет
(«0 is not a fill», строка оставляется с `fill_price_unconfirmed`), для выхода
симметричной защиты нет. Достижимо двумя способами:

1. брокер вернул терминальный `filled` без цены исполнения в детали заявки
   (`fillPriceFrom(detail) == 0`, `unconfirmedPrice == true`);
2. оператор вызвал `ResolveTracker(id, "filled", note, 0, qty)` — `filledPrice`
   там необязательный, при 0 ключ в `detail` просто не ставится.

Если есть обе строки (монитор + брокер), выполняется парная ветка → обе
закрываются с `exit_price = 0`, `pnl_percent ≈ -100`. Если строка одна, идёт
`closeTradeWithPnL` → `CloseTradeByID` → отказ и `raiseTrackerPersistBlock`,
то есть шумно, но без порчи данных. Асимметрия и есть корень.

Доказательство:

```
CloseTradePair("m-o1","o1", 0, "2026-09-02", ...) → err=nil
row: exitPrice:0 pnlAbsolute:-99.999999 pnlPercent:-99.999999 status:closed
```

### AUD-041 — `pnl_absolute` живого журнала не учитывает количество

`TradeCloseFields` ([`db.go:1362`](../../go/internal/store/db.go)) пишет
`pnlAbsolute = round6(exitPrice - entryPrice)` — разницу **на одну акцию**.
Колонка `quantity` в тех же таблицах есть и заполняется фактическим
исполнением.

SPA показывает это значение как денежный результат:
`app.js:2653` — `<td>${fmtUsd(t.pnlAbsolute)}</td>` в таблице журнала прямо
рядом с колонкой «Кол-во» под заголовком «PnL, $» (`app.js:2675`);
`app.js:1599` берёт то же поле для строки «PnL» таблицы сделок монитора.
Для позиции в 10 акций (вход $100, выход $110) в интерфейсе будет «$10.00»
вместо «$100.00» — занижение ровно в `quantity` раз. Бэктест этим полем не
пользуется (там свой `types.Trade.PnL`), затронут только живой журнал и его
экспорт CSV (`app.js:4070`).

### AUD-042 — валидацию порогов watch обходит строковое значение

`validateWatchThresholds` ([`server.go:1381`](../../go/internal/httpapi/server.go))
читает пороги только через `body["lowIBS"].(float64)`, а `watchHasThresholdKey`
проверяет лишь наличие ключа. Строка проходит проверку как «поле не задано»,
после чего `UpsertWatch` → `watchFloatOrDefault` → `asFloat`
([`db.go:1338`](../../go/internal/store/db.go)) её честно парсит.

`POST /api/telegram/watches` с телом `{"symbol":"QQQ","lowIBS":"0.9","highIBS":"0.95"}`
проходит валидацию без ошибки и сохраняет `lowIBS=0.9`, `highIBS=0.95` —
пороги, которые `ibs.SanitizeThresholds` бы не пропустил как пару, и при
которых вход срабатывает практически на любом IBS. Глобальные пороги в
`sanitizeAutoTradingConfig` защищены (`finiteNumber` + `SanitizeThresholds`),
дыра только в per-watch пути.

Проверено: `validateWatchThresholds(body, nil)` → `nil`;
`UpsertWatch` → `ListWatches` → `highIBS:0.95 lowIBS:0.9`.

## Разобрано и признано корректным

- **Пороги строгие с обеих сторон.** И бэктест (`single.go`, `clean.go`), и
  живой контур (`decideLiveAction`, `evalWatch`) идут через
  `ibs.IsEntrySignal`/`IsExitSignal`; IBS ровно `0.10` входом не считается.
- **Маржин-колл в `single.go`.** `marginLiquidationPrice` выведена из того же
  условия, что и `SimulateMargin` (капитал ≥ 25% рыночной стоимости),
  свободные деньги входят в капитал, в день входа ликвидации нет
  (`bar.Date > current.entryDate`).
- **Нет заглядывания вперёд.** Позиция, открытая на баре D, впервые
  проверяется на выход на D+1: блок выхода в дневном шаге стоит до блока
  входа. Take-profit по `bar.High` от этого дня — уже честный.
- **Даты.** Торговые даты в разобранных путях — строки; `time.Time`
  встречается только в wall-clock (`CurrentTimeNYSE`, дедлайн T-1, TTL кэша
  котировок) и на границе с внешними API. Тесты зелёные в двух зонах.
- **Идемпотентность отправки.** `placeMarket` выбирает `clientOrderId` до
  запроса, при неоднозначном сбое спрашивает брокера по этому же id и никогда
  не шлёт второй MARKET вслепую; `queryFailed` → `Ambiguous`, трекер
  сохраняется, вход блокируется.
- **Дедлайн T-1.** Один `execWindow` на весь цикл (reconcile → выход → вход),
  первая попытка уходит всегда, следующая — только если укладывается в остаток.
- **Кэш котировок 20 с** не даёт T-1 переиспользовать значения T-11: решение
  считается по свежим данным того же окна.
- **Размер заявки.** `ComputeOrderQuantity` вычитает резерв из средств до
  деления, `math.Floor` только уменьшает — инвариант
  `qty*price ≤ funds*(1-reserve)` держится; выход продаёт ровно то, что у
  брокера, без округления вниз.

## Известные упрощения (не находки)

- `metrics.alpha` считает `cagr - (2 + beta*(8-2))`: безрисковая ставка 2% и
  доходность рынка 8% зашиты константами. Значение сопоставимо только само с
  собой.
- `EvaluatePriceIntegrity` пропускает проверку (`Checked=false`), когда
  последний бар старше предыдущего **буднего** дня: после биржевого праздника
  проверка сплитов не отрабатывает. Направление — «блокируем реже».
- В `RunEmaZone` маржин-колл не моделируется вовсе; CLAUDE.md описывает
  маржинальную механику только для `single-position`.
